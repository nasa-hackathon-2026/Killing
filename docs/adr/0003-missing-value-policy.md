# 缺值政策：趨勢檢定不補值，探勘在距平上補

## 背景

序列有缺月。趨勢檢定可以容忍缺月，資料探勘（FP-growth、決策樹）需要完整的「地點 × 月份」表。

## 決定

| 用途 | 做法 |
|---|---|
| 趨勢檢定 | **不補值**，用 `value_clean`（`clean.trend_input`） |
| 資料探勘 | 在**距平**上補（`anomaly_filled`）：連續缺 ≤ 2 個月用前後可用月份線性內插；更長的缺口補距平 0（也就是月氣候值）；第一個可用月份之前與最後一個之後不外推；不用前一個月的值帶入 |
| | 補值比例（補的月數 ÷ 第一個到最後一個可用月份之間的月數）超過 20% 的序列不用（`mining_eligible = false`） |

每個補的值都有 `fill_method`（`linear`／`climatology`）；`value_clean` 與 `anomaly` 不被補值改動。門檻在 `data/seed/cleaning.json`（`max_linear_gap_months`、`max_fill_fraction`）。

## 理由

- 趨勢檢定不補：補值會人為提高自相關、壓低變異，使檢定偏樂觀。
- 不用前值帶入：會製造假的持續性。
- 20% 沿用趨勢統計既有的 `max_missing_fraction`。

## 替代方案

- **趨勢也補值**：見上，沒有採用。
- **探勘不補值（缺月的列丟掉）**：每次探勘都另跑一次這個版本當敏感度比較（結果檔的 `gap_filling_sensitivity`）；2026-11-15 兩種做法的前 10 條規則相同，決策樹都是 0 折高於全部基準。
- **用模型補值**：未評估。#117 要比較自編碼器與現行政策。

## 後果

- 用 `anomaly_filled` 訓練或評估模型時，要用 `fill_method` 排除補出來的月份，否則是在預測我們自己補的值。
- 長缺口補 0 會把那段期間的變異壓成 0。

**缺值該怎麼處理（沿用前一個月的值，或用平均平滑）是 Grason 在 2026-11-14 提出的問題；這份政策由 AI 工具在 2026-11-15 提出，Grason 檢視後決定採用。隊伍可以改。** 改法：調 `data/seed/cleaning.json` 的門檻，重跑 `pg clean`、趨勢與探勘。
