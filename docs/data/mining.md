# 資料探勘的補強（#111）

三項探索性分析的問題、方法、防止資料洩漏的做法、對照的基準、結果與限制。既有的關聯規則（FP-growth）與預測植被指數的決策樹見 `AGENTS.md`「如何重產分析結果」與 `src/trend_detective/mining.py` 開頭。網頁在 `/mining/`。

限制先講：

- **全部是探索性結果，只列數字，不寫因果，也不解釋「為什麼」。** 結果檔都標 `exploratory: true`。
- 參數在跑之前定好，寫在各模組的參數 dataclass 與結果檔的 `parameters`；跑過的版本全部列出，沒有為了得到結果而調整。
- 顯著性的修正只處理 lag-1 自相關，是近似；同一張表的地點彼此相鄰，不是獨立樣本。
- 相似序列需要清洗資料庫（pgvector 的向量）；差距決策樹與變數關聯圖只讀 repo 裡的檔案（關聯圖的 pgRouting 核對才需要資料庫）。

## 怎麼重跑

```bash
uv run python -m trend_detective.gap_tree                 # 約 3 秒；加 --write-db 另寫回 analysis.gap_tree_folds、analysis.gap_stats
uv run python -m trend_detective.variable_graph           # 約 3 秒；會連資料庫跑 pgRouting（寫 analysis.correlation_nodes／correlation_edges）
uv run python -m trend_detective.variable_graph --no-db   # 不連資料庫；結果檔的 pgrouting 是 null
uv run python -m trend_detective.similar_series           # 約 3 秒；需要資料庫（pg load、clean、derive 之後）
```

先後順序：`trends` →（`model_obs`）→ 這三個。在 worktree 裡設 `TREND_DETECTIVE_ENV_FILE=<主 checkout>/.env`。資料沒變時重跑，三個結果檔都逐位元組相同（2026-11-15 各跑兩次核對；時間戳只在 `*.run.json`）。資料庫的表在 `db/migrations/023_mining_plus.sql`（可重跑）。

## 1. 模式與觀測的差距在什麼條件下比較大

**問題**：台灣測站的氣溫配對裡，「模式距平 − 測站距平」的絕對值（以下稱差距）在哪些月份、哪些測站、哪個模式產品比較大。不判斷模式或觀測誰對。

**資料**：`model_vs_obs.json` 的 `taiwan_station` 配對，`station_temp` 對 `gldas_tair`、`merra2_t2m`，共 11 對、6 個測站、3,273 個配對月（2001-01 至 2025-12）。`power_t2m` 不用：它提供的就是 MERRA-2 的場，與 `merra2_t2m` 是同量變數，而且只有 2 站。蘭嶼沒有 GLDAS 配對（GLDAS 只有陸地格）。世界城市的 GHCNm 配對這一輪沒有納入：`model_vs_obs.json` 對世界城市只存年平均，逐月差值要從資料庫重新產生（見「沒有做的」）。

### 決策樹

- **目標**：差距分三級（small／medium／large），門檻是訓練列（全部配對合併）的 1/3、2/3 分位數，測試列不重新切。
- **特徵**：日曆月；模式產品（是否 GLDAS）；GLDAS 分段編號（只有 GLDAS 配對有值，MERRA-2 配對是 0）；測站（one-hot，留一地點時不放）；最近的核心點位上 8 個非溫度類變數（`airs_h2ovap`、`gldas_evap`、`gldas_soilmoist`、`imerg_precip`、`modis_ndvi`、`omi_aerosol`、`omi_no2`、`omi_o3`）當月去趨勢距平的分級（−1／0／1，沿用探勘的三分位）；測站距平本身的分級。
- **環境特徵取自最近的核心點位**：Hengchun → `kaohsiung`（84.0 km）；Kaohsiung International Airport → `kaohsiung`（7.8 km）；Lanyu → `kaohsiung`（144.7 km）；Taichung → `taichung`（0.0 km）；Tainan → `kaohsiung`（42.0 km）；Taipei → `taipei`（5.2 km）。南部三站與蘭嶼都用高雄點位，蘭嶼相距 145 km。
- **樹**：深度上限 3、葉節點至少 20 列、`random_state = 0`（沿用 `mining.py` 的設定）。

**防止資料洩漏**

| 做法 | 在哪裡 |
|---|---|
| 模式距平、觀測距平、差值的連續值不得當特徵（兩者相減就是目標）；溫度類變數（分類路徑含 `temperature`：`airs_tsurf`、`gldas_tair`、`merra2_t2m`、`modis_lst`、`power_t2m`）不當特徵；目標自己前一個月的類別預設不當特徵 | `check_feature_names`，名稱不合就中止 |
| 任何單一特徵（深度 2 的樹）在訓練列上的準確率超過 0.95 就中止 | `check_single_feature_leak` |
| 走動驗證每一折的日曆月平均（重新置中）、線性趨勢、環境變數與測站距平的分位數門檻、目標的門檻，都只用該折的訓練月份估計 | `recenter`、`fold_states`、`build_rows`；測試：改掉測試期的值，訓練列的特徵、類別與門檻不變 |
| 留一地點時不放測站特徵；目標門檻只用訓練測站 | `build_rows(with_station=False, train_stations=…)` |

留一地點的訓練列與測試列在同一段時間，鄰近測站同一個月的天氣相同，所以它檢查的是「換一個地點」而不是「預測未來」；各序列的距平與分級在這個驗證裡用自己全期估計（不看類別）。

**基準**（都不使用其他變數）：永遠猜訓練列最多的類別（`train_majority`）；猜這一對上個月的類別（`persistence`）；猜訓練列裡該日曆月最多的類別（`calendar_month`）。「高於全部基準」是嚴格大於這三個。另列 `hindsight_test_majority`（永遠猜測試列最多的類別），那是事後才知道的對照，不算在內。

## 2. 變數關聯圖

**問題**：哪些變數的月距平在同一個月、或相差一個月時，傾向一起偏高或偏低。邊是相關，不是因果。

**做法**：台灣核心序列的月距平（已去月氣候值）再各自減掉線性趨勢，不補值，每一對只用兩邊都有值的月份（至少 120 個月）。點位表 5 個點位、區域表 4 個區域（`taiwan` 與其他區域重疊，不用）。每一對變數算同月、以及落後一個月（兩個方向各一次）的相關係數。表內合併的 r 是各地點標準化後接在一起算；檢定用的有效樣本數取**各地點有效樣本數的中位數**（地點彼此相鄰，不相加）。有效樣本數 `n × (1 − r1x·r1y) ÷ (1 + r1x·r1y)`，r1 用 `trends.lag1_autocorrelation`。同一張表全部檢定一起做 BH-FDR，q < 0.05 的是圖上的邊。

**排除**：同量變數的配對（`same_quantity_groups`：兩套 NDVI、兩套地表溫度、各種氣溫產品彼此）不檢定，列在各表的 `excluded_pairs`。趨勢統計標為資料不足的序列不放。

## 3. 相似序列

**問題**：某個地點的某個變數，和哪些其他變數（可以在別的地點）的月距平在同樣的月份偏高、偏低。

**範圍**：網站上看得到的序列——台灣 5 個點位、12 個世界城市、全球平均，乘上 12 個核心圖層變數（世界城市與全球沒有 MODIS）。有向量的共 185 條（台灣 57、世界城市 118、全球 10；台灣 60 條裡 3 條 `omi_no2` 不符合探勘條件，沒有向量）。候選也只在這 185 條裡找：資料庫另有六千多條擴充序列，多半是同一個產品的其他層或晝夜版本，放進來前幾名會全是近乎重複的變數（`postgres.md` 的 pgvector 範例就是這樣）。

**做法**：向量來自 `analysis.series_embeddings`（`011_vector.sql`）：2005-01 至 2025-08 共 248 個月的距平（去掉整條序列的月氣候值，缺月依補值政策補），標準化成平均 0、標準差 1，所以 cosine 相似度等於這段期間距平的 Pearson 相關係數；**向量沒有去趨勢**。每條序列列出相似度最高的 5 條與最低（最負）的 3 條不同變數的序列，同量變數不列。

**顯著性**：相似度當成相關係數，用兩條序列各自 lag-1 自相關修正後的有效樣本數做 t 檢定。BH-FDR 的範圍是這一批裡**全部可列的配對**（不同變數、非同量，14,577 對），不是只有列出來的——只對挑出來的前幾名校正會偏樂觀。不顯著的照樣列，標 `significant: false`。

**共同趨勢**：兩條都先減掉自己的線性趨勢、重新標準化，再算一次（`cosine_detrended`，另做一次檢定與 FDR）。兩個相似度相差超過 0.1 或正負號相反的標 `trend_sensitive`。

**核對**：資料庫用 pgvector 的 `<=>` 對同一批序列兩兩算的相似度，與 numpy 算的最大絕對差 1.8e-7（向量存成 float4），在容許值 1e-5 內（`check.pgvector_matches_numpy`）。
