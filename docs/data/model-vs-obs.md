# 模式推算 vs 觀測（#97）

同一地點、同一個物理量（近地面氣溫）的「模式或再分析推算的序列」與「觀測序列」放在一起比：共同期間的距平相關、差值、各自的趨勢、趨勢差、差值序列的最大階梯。規則在 `data/seed/model_obs_pairs.json`，算法在 `src/trend_detective/model_obs.py`（純函式，測試不連資料庫），結果在資料庫的 `analysis.model_obs_pairs` 與 `data/analysis/model_vs_obs.json`，網站的「Model vs observation」頁（`web/compare/`）讀後者。

限制先講：

- **這份文件只列數字，不判斷誰對。** 模式與觀測有差，光憑這個差不能說哪一邊正確；兩邊各自的已知問題見表的最後一欄與「限制」。
- 只有氣溫。蒸散與土壤水沒有觀測可以配（見「限制」）。
- 距平是在共同月份上各自去月氣候值算的，所以兩條距平與差值的平均都是 0：這裡看不到絕對偏差（模式比測站高或低幾度），只看得到變化是否一致。
- 需要清洗資料庫（`pg load`、`pg clean`）與 `data/observed/`、`data/raw/grid/` 的格點立方體；公開 demo 只讀匯出的 JSON。

## 怎麼重算

```bash
uv run python -m trend_detective.model_obs     # 97 對約 15 秒；在 worktree 加 --raw-grid-dir <主 checkout>/data/raw/grid
```

整批換新 `analysis.model_obs_pairs`，寫一列 `analysis.runs`（`step = 'model_obs_pairs'`），並重寫 `data/analysis/model_vs_obs.json` 與 `model_vs_obs.run.json`。

合計 97 對，全部有統計量。另有 1 對沒有配成：`gldas_tair` 對蘭嶼測站——GLDAS 只有陸地格，蘭嶼座標所在格與周圍 2 格內都沒有值。

**測站所在格的取法。** 台南、恆春、蘭嶼、高雄機場 4 站沒有對應的模式點位序列，所以 6 個測站一律從格點立方體（`data/raw/grid/<變數>/<變數>.nc`，GLDAS 0.25°、MERRA-2 0.5° × 0.625°，原始解析度）取「格心離測站座標最近的那一格」，也就是座標所在格，逐月讀值。沒有用 `geo.monthly_rasters`：那裡是降到 1° 的 raster，對測站太粗。座標所在格整條都沒有值時（GLDAS 的海面格），取上下左右各 2 格內、有值、格心最近的格子；台南與恆春的 `gldas_tair` 是這種情況（格心距測站 17 km、19 km）。每一對用的格心、格距、距離、是不是座標所在格都記在 `analysis.model_obs_pairs.model_detail` 與 JSON 的 `model.detail`。立方體的值沒有經過清洗的旗標（沒有 `coverage`）；資料庫序列用的是清洗後的 `value_clean`。

**不配成同一對的量。** 地表溫度不是氣溫：MODIS LST（`modis_lst`、`modis_lst_pc`）是晴空下地表的輻射皮溫；AIRS 的 `airs_tsurf` 是衛星反演的近地面氣溫，屬於觀測而不是模式，AIRS 皮溫（`surfskintemp`）又是另一個量。這些列在規則檔與 JSON 的 `related_not_same_quantity`，沒有算統計量。`gistemp_land_anom`（僅陸地版）這一輪也沒有配。

## 做法

1. **共同期間**：視窗 2001-01 至 2025-12 內，兩條序列都有可用值的月份。只用這些月份；兩邊的趨勢因此是「同月份樣本」的趨勢，和 `data/analysis/trends.json` 裡各序列用自己全部月份算的趨勢不同。共同月份不到 120 個不算。
2. **距平**：兩條序列各自在共同月份上取每個日曆月的平均，再相減。理由：GISTEMP 是相對 1951–1980 的距平、測站與 GHCNm 是 °C 的絕對值、模式是 K 的絕對值；各自在同一批月份上去掉自己的月氣候值之後，基期、絕對值與距平、°C 與 K 的差別都消掉（1 K 的差等於 1 °C 的差）。
3. **統計量**：兩條距平的 Pearson 相關；差值（模式 − 觀測）的平均、標準差、RMSE；兩條距平各自的最小平方法趨勢與 95% 信賴區間（`trends.ols_trend`，lag-1 自相關修正後的有效樣本數，和趨勢統計同一個函式）；趨勢差（模式 − 觀測）；差值序列本身的趨勢、信賴區間與是否顯著（p < 0.05）。差值序列的趨勢在數值上等於趨勢差，但它有自己的信賴區間：兩條序列共有的年際變化在差值裡抵消，所以區間比兩邊各自的窄。這裡沒有做多重檢定校正。
4. **最大階梯**：沿用 [gldas-tair-check.md](./gldas-tair-check.md) 的做法——差值序列在每個月份 m 算「m 起 6 個月的平均 − m 之前 6 個月的平均」（兩邊各至少 4 個月有值），取絕對值最大的那一個；月份是新的一段開始的月份。這只是找出最大的那一個，不是檢定；雜訊大的差值序列也一定會有一個「最大階梯」。
5. **已知問題**：兩邊序列適用的 `meta.known_issues` 都帶上（模式取自立方體時，依變數與地點比對）。
6. **匯出**：台灣與全球的配對有逐月的兩條距平與差值；世界城市只有統計量與逐年平均（當年共同月份不到 9 個是 null），檔案約 350 KB。

## 限制

- **測站是點、模式是格。** 測站量的是一個點的氣溫，模式值是一格（GLDAS 約 25 km、MERRA-2 約 50 × 65 km）的平均，格子裡有海面、山地與都市；台灣測站多在市區、機場與海邊。差值不全是模式誤差，也不全是測站的代表性問題。台南、恆春的 GLDAS 值來自鄰格。
- **GISTEMP 不是單點實測。** 它是測站（GHCN v4，均一化）與船舶、浮標觀測的 2° 格點化分析，1200 km 平滑；高雄、花蓮、玉山在同一格，台北、台中在同一格，所以 `taiwan_gistemp` 的 15 對只有 2 條不同的觀測序列，各對之間不獨立。GISTEMP 的台灣格也含海面溫度。
- **GISTEMP 與 GHCNm 不獨立。** GISTEMP 的陸地部分用的就是 GHCNm v4 的均一化資料；同一城市對 `ghcnm_tavg` 與對 `gistemp_anom` 的兩對不是兩個獨立的驗證。
- **高雄國際機場的觀測頻率改變。** 每日觀測筆數的中位數由約 24（2001–2005）變成 44（2021–2025）；2001–2025 的趨勢用全部觀測是 0.465 °C／十年、只取 3 小時一筆是 0.334（[sources/ghcnh_taiwan.md](./sources/ghcnh_taiwan.md)）。表裡用的是全部觀測的月均溫，這一站的觀測趨勢含有這個效應；已知問題 `station_temp_kaohsiung_airport_sampling`。
- **GHCNm 調整版與未調整版。** `ghcnm_tavg`（QCF）經 NOAA 的成對均一化調整，`ghcnm_tavg_unadj`（QCU）只做品管。兩者的趨勢在同一站可以差到 0.2 °C／十年以上（例如東京 +0.64 對 +0.42）；哪一版比較接近真實的氣候變化，這裡沒有判斷。測站是離城市中心 100 km 內的最近站，不等於城市中心。
- **GLDAS 的氣溫是強迫輸入。** `gldas_tair` 來自 NOAA GDAS 分析場，已知在 2011-05、2017-07、2019-06 有階梯（[gldas-tair-check.md](./gldas-tair-check.md)）；`power_t2m` 提供的就是 MERRA-2 的場，和 `merra2_t2m` 不是兩個獨立的模式。
- **測站少，台灣東部沒有站。** 6 個站裡 3 個在南部、1 個離島，東部與山區沒有；GHCNm 的台灣測站在 2013-12 以前都結束了，所以台灣沒有 GHCNm 的配對（已知問題 `ghcnm_taiwan_no_data_after_2013_12`）。
- **缺月。** 5 個氣象署測站在 2001-02、2017-05、2022-07 沒有月平均，共同月數是 297；缺月不補。最大階梯的 6 個月平均在這些地方少一個月。
- **蒸散與土壤水沒有觀測可配。** SMAP 在建議品質過濾下台灣 0 筆有效反演（[sources/smap.md](./sources/smap.md)，已知問題 `smap_taiwan_no_recommended_retrievals`）；本專案沒有蒸散的觀測。`gldas_evap`、`gldas_soilmoist` 目前只有模式對模式的對照（[gldas-water-check.md](./gldas-water-check.md)）。
- **共同期間的月氣候值**用的年份比各序列自己的全部年份少（最多 25 年），日曆月的平均有抽樣誤差。

## 用 SQL 查

```sql
-- 台灣測站：相關、兩邊趨勢、趨勢差、最大階梯
SELECT location_id, model_variable_id, n_common_months, round(correlation::numeric, 2) AS r,
       round(model_slope_per_decade::numeric, 2) AS model, round(obs_slope_per_decade::numeric, 2) AS obs,
       round(slope_difference::numeric, 2) AS diff, largest_step_month, known_issues
FROM analysis.model_obs_pairs WHERE pair_group = 'taiwan_station' ORDER BY 1, 2;

-- 模式值取自鄰格（座標所在格沒有值）的配對
SELECT pair_id, model_detail->'cell_center', model_detail->>'distance_km'
FROM analysis.model_obs_pairs WHERE model_detail->>'containing_cell' = 'false';
```
